# RecSys Evaluation Bot

Асинхронный Telegram-бот для автоматического тестирования сервисов рекомендаций.
Бот собирает необходимые параметры от студента, проверяет работоспособность
сервиса и проводит нагрузочное тестирование с заданным RPS, после чего выставляет
финальные ML-метрики (Precision/Recall). Все результаты логируются в публичную
Google-таблицу.

## Зависимости и Стек

- [uv](https://github.com/astral-sh/uv) (быстрый пакетный менеджер для Python)
- Docker & Docker Compose
- `aiogram` v3
- `aiohttp` (тестирование API)
- `pandas` (расчет метрик)
- `gspread` (интеграция с Google Sheets)

## Подготовка данных (`test.csv`)

Для корректной работы бота требуется скрытый тестовый датасет, на котором считаются
метрики качества рекомендаций по каждому пользователю. Этот файл должен лежать по пути:
`test.csv` (в корне проекта).

### Формат данных

Файл `test.csv` должен быть в формате CSV с запятой (`,`) в качестве разделителя,
и содержать как минимум следующие колонки:

1. `user_id` (integer) — идентификатор пользователя. Уникален или дублируется для
каждого просмотренного им айтема в зависимости от формата, однако бот сгруппирует
взаимодействия для получения полного списка ожидаемых айтемов.
2. `item_id` (integer) — идентификатор контента, который пользователь реально
посмотрел (ground truth).

Пример `test.csv`:

```csv
user_id,item_id,timestamp
1023,551,1620002123
1023,12,1620002130
4551,33,1620002150
```

*Бот итерируется по уникальным `user_id` из этого файла для генерации запросов:
`GET /reco/{model_name}/{user_id}`.*

## Настройка Окружения (`.env`)

Для запуска бота скопируйте `bot/.env.example` (или создайте файл `.env` в корне
проекта) и заполните его.

*(Обратите внимание: чтобы бот мог писать в таблицу `GOOGLE_SHEET_URL`, в ней нужно
выдать доступ "Редактор" на email из Service Account: `xxx@yyy.iam.gserviceaccount.com`)*

## Как получить аккаунт для Google таблички

1. Зайдите в [Google Cloud Console](https://console.cloud.google.com/).
2. Создайте новый проект (или выберите существующий).
3. В разделе **APIs & Services > Library** найдите и включите:
    - Google Sheets API
    - Google Drive API
4. Перейдите в **APIs & Services > Credentials**.
5. Нажмите **Create Credentials > Service Account**.
6. Заполните название и создайте аккаунт. Разрешения (roles) можно не выбирать (нажмите Done).
7. В списке Service Accounts нажмите на созданный аккаунт, перейдите на вкладку **Keys**.
8. Нажмите **Add Key > Create new key**, выберите формат **JSON**. Скачайте файл.
9. Содержимое этого файла — это и есть `GOOGLE_CREDS_JSON`. Вы можете либо указать
путь к этому файлу в `.env`, либо вставить его содержимое одной строкой.
10. **Важно:** Откройте вашу Google-таблицу и нажмите кнопку **Share** (Поделиться). Добавьте email вашего Service Account (`client_email` из JSON-файла) с правами **Editor** (Редактор).

## Инструкция по запуску

### Через Docker (Production)

```bash
make setup
docker-compose up -d --build
```

### Локально для разработки

1. Установите `uv`
2. `make setup`
3. Подложите `test.csv` и `.env`
4. Выполните:

   ```bash
   make run
   ```

### Как проверить, что все работает?

1. **Логи бота:** При запуске `make run` в консоли должны появиться строки о
загрузке пользователей: `Загружено X уникальных пользователей из test.csv`.
2. **Telegram:** Найдите своего бота в Telegram и отправьте команду `/start`.
Если бот ответил приветственным сообщением — он "ожил".
3. **Пробный тест:** Попробуйте отправить боту ссылку на любой работающий сервис
(или просто заглушку), чтобы убедиться, что он перешел к выбору RPS.
